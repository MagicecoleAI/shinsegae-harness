# 8시간 Build Day

오전에는 작동 결과를 만들고, 오후에는 사람이 검토할 구조와 실패 기록을 만듭니다. 기능 수가 아니라 **작동·검증·재현·다음 결정**이 완료 기준입니다.

## 하루 운영 원칙

- 2주차 v2.0의 사용자·입력·결과를 다시 늘리지 않습니다.
- 주 Starter 하나만 선택합니다.
- 12시까지 화면이 아니라 첫 결과파일을 만듭니다.
- 14시 35분부터는 새 기능보다 테스트를 우선합니다.
- 외부 연결이 실패하면 저장 Sample과 Mock 결과로 전환합니다.
- 실패한 테스트는 숨기지 않고 4주차 Backlog로 넘깁니다.

## Gate 1 · 09:30 Scope Lock

아래 일곱 가지가 모두 열려야 합니다.

- 2주차 프로젝트 v2.0
- 팀 Starter와 출처 기록
- Sample Input
- Expected Output
- Test 10개 초안
- Claude Code 프로젝트 폴더
- 인터넷 없이 사용할 Fallback

하나라도 준비되지 않았다면 자료를 더 찾느라 시간을 쓰지 말고 제공된 Sample로 전환합니다.

## Gate 2 · 12:00 Bronze

```text
고정 Sample Input 1개
→ 필수 입력 검사
→ 핵심 업무규칙 1개
→ 결과파일 1개
```

### Bronze가 안 되면

1. 외부 API와 실시간 수집을 삭제합니다.
2. UI를 삭제합니다.
3. 여러 입력을 한 입력으로 줄입니다.
4. 결과 형식을 Markdown 하나로 줄입니다.
5. AI 판단 대신 명시 규칙과 사람 확인을 사용합니다.

## Gate 3 · 14:35 Silver

결과에서 다음이 보여야 합니다.

- 사용한 입력과 기준일
- 결과를 만든 근거 또는 원본 위치
- 잘못된 입력과 누락 항목
- AI가 결정하지 않은 항목
- 사람이 수정·승인할 위치

14시 35분 이후에는 멘토가 승인하지 않은 기능을 추가하지 않습니다.

## Gate 4 · 17:00 Gold Candidate

| 확인 | 완료 기준 |
|---|---|
| 핵심 흐름 | 같은 Sample로 다시 실행됨 |
| Test | 정상 4·경계 3·오류 2·금지 1 실행 |
| Fallback | 외부 연결 없이 실행 가능 |
| README | 다른 팀원이 5단계 안에 재현 |
| Demo | 문제·입력·결과·검토·실패를 3분에 설명 |

## 멘토링 질문

멘토에게 “잘 만들었나요?”라고 묻지 말고 다음처럼 묻습니다.

```text
현재 Bronze 결과는 [파일]입니다.
Expected Output과 다른 점은 [한 가지]입니다.
가장 큰 실패는 [테스트 ID]입니다.
남은 시간에 [A]를 고칠지 [B]를 삭제할지 결정이 필요합니다.
어느 선택이 핵심 흐름 검증에 더 중요한가요?
```

## Claude Code 작업요청 카드

```text
1. 이번 작업:
2. 사용할 입력:
3. 만들어야 할 결과:
4. 변경해도 되는 파일:
5. 지켜야 할 업무규칙:
6. 완료 확인방법:
7. 하지 말아야 할 것:
```

{: .important }
> 작업이 끝나면 Claude의 설명만 읽지 말고, 바뀐 파일과 실제 실행 결과를 직접 확인합니다.

## Blocker 대응

| Blocker | 10분 안에 할 일 | 20분 뒤 결정 |
|---|---|---|
| 패키지 설치 실패 | 이미 있는 표준 라이브러리로 대체 | 설치 없는 Markdown/CSV 흐름 |
| 외부 API 실패 | 저장 Snapshot 사용 | API를 4주차로 이동 |
| 데이터 형식 복잡 | 공통 더미 형식으로 변환 | 입력 1종만 지원 |
| 결과 정확도 흔들림 | 명시 규칙과 원본 위치 표시 | AI 판단을 사람 확인으로 전환 |
| UI 실패 | 결과파일을 직접 열기 | UI 삭제, 데모 Backup 사용 |
