# 8월 21일 · 샘플 체험에서 실제 Agent 결정까지

오전에는 강사의 실제 Claude Code 사용을 본 뒤 5개 팀이 자기 업무와 유사한 샘플 미니앱을 만들고 시행착오를 경험합니다. 오후에는 샘플과 실제 업무의 차이를 분석해 8월 28일 완성할 Agent 주제·변경·개선점을 결정하고 결과물을 약속합니다.


## 09:00 · 강사 Live Demo

강사는 완성 코드를 보여주는 사람이 아니라 **AI에게 일을 맡기고 통제하는 사고과정**을 보여줍니다.

```text
1. 변경 전 앱을 실제 실행한다.
2. Claude가 파일을 먼저 읽게 한다.
3. 수정 전 작업계획·파일·완료기준을 요청한다.
4. 사람의 판단으로 계획을 줄인다.
5. 한 기능만 구현한다.
6. 바뀐 파일과 실제 화면을 확인한다.
7. 오류·예상차이를 다시 제공하고 수정한다.
8. 다른 관점의 Reviewer로 검증한다.
9. 완료·실패·다음 작업을 기록한다.
```

### 경험자가 독점하지 않게 한다

| 역할 | 오전 행동 |
|---|---|
| 초보 Navigator | 첫 Prompt·변경요구 작성, 계획에서 삭제할 것 제안 |
| 지정 Driver | Claude Code 입력·파일변경·실행 |
| Verifier·Recorder | 원하는 결과·실패·사람 확인·회고 기록 |

20~30분마다 Prompt 작성자와 결과 설명자를 바꿉니다. 계정 비밀번호는 공유하지 않습니다.

## 11:20 · 시행착오 회고

팀은 설명이 아니라 실제 파일·화면·오류를 보면서 답합니다.

- 처음 막힌 단계는 무엇인가?
- 잘된 Prompt와 너무 큰 Prompt는 무엇인가?
- Claude의 계획에서 사람이 삭제·수정한 것은 무엇인가?
- 설명과 실제 결과가 달랐던 것은 무엇인가?
- 오류를 어떤 정보로 다시 전달했는가?
- 샘플에서 실제 업무에도 적용할 것은 무엇인가?
- 샘플이라 가능했지만 실제 업무에는 적용하지 않을 것은 무엇인가?

## 8월 28일 결과물 약속

다음 표현은 약속이 아닙니다.

- “고도화하겠습니다.”
- “정확도를 높이겠습니다.”
- “API를 연동하겠습니다.”

다음처럼 씁니다.

```text
8월 28일 [예시 입력]으로 [최종 결과]를 실제 실행하고,
[시험·README·시간 비교]로 완료 여부를 증명한다.
[날짜]까지 [핵심 기능]이 작동하지 않으면 [부가기능]을 제외한다.
```
