# 평가와 발표

잘 작동한 화면보다 **무엇을 검증했고, 어디서 실패했으며, 사람이 어떻게 통제하는지**를 보여주는 팀이 더 강합니다.

평가는 오전 샘플 미니앱의 완성도가 아니라 `Claude Code 사용과 시행착오`, 오후 실제 Agent의 `주제·변경·개선·완료약속`을 함께 봅니다.

## 오전 샘플 체험 평가

| 확인영역 | 증거 |
|---|---|
| Claude가 먼저 읽었는가 | 파일·입력→결과 설명 |
| 사람이 계획을 통제했는가 | 삭제·수정한 계획 |
| 경험 적은 팀원이 참여했는가 | Prompt 작성·결과설명·시험 기록 |
| 실제로 실행했는가 | 화면·결과파일·Terminal |
| 실패를 다뤘는가 | 오류·예상차이·수정·재실행 |
| 샘플을 실제 업무와 구분했는가 | 적용·비적용·확인질문 |

## 독립 평가 순서

Builder가 자신이 만든 결과를 혼자 합격시키지 않습니다.

1. Verifier가 고정 Sample로 대표 시나리오를 다시 실행합니다.
2. Expected Output의 필수 항목을 실제 결과와 비교합니다.
3. Test 10개를 `PASS / PARTIAL / FAIL / BLOCKED`로 판정합니다.
4. Owner가 업무 규칙·민감정보·사람 승인 위치를 확인합니다.
5. 다른 팀원이 README만 보고 한 번 재현합니다.

## 공통 평가표

| 영역 | 질문 | 0점 | 1점 | 2점 |
|---|---|---|---|---|
| 문제 적합 | 실제 반복 업무 한 장면을 다루는가? | 불명확 | 일부 연결 | 사용자·입력·결과 명확 |
| 작동 | 입력에서 결과까지 재현되는가? | 미작동 | 수동 보조 | 같은 Sample로 재현 |
| 근거 | 결과의 원본·기준일을 찾을 수 있는가? | 없음 | 일부 | 핵심 결과 모두 추적 |
| 안전 | 금지정보·금지행동을 중단하는가? | 통제 없음 | 문구만 있음 | 테스트로 확인 |
| 사람 승인 | AI와 사람 결정이 분리되는가? | AI 자동 확정 | 확인 문구 | 승인 상태·항목 명확 |
| 실패 대응 | 오류와 Fallback이 있는가? | 실패 숨김 | 설명만 있음 | 실제 Fallback 실행 |
| 재현 | 다른 팀원이 다시 실행하는가? | 불가 | 도움 필요 | README만으로 가능 |
| 다음 계획 | 개선 순서가 현실적인가? | 기능 나열 | 우선순위 있음 | 담당·기한·완료기준 |

총점 16점보다 중요한 것은 **0점인 안전·근거·사람 승인 항목이 없는가**입니다.

## 발표 전 최종 확인

- [ ] Live Demo와 저장된 Backup 결과가 모두 있다.
- [ ] 참가자 이름·실제 회사 수치·내부 화면이 보이지 않는다.
- [ ] 입력과 결과가 한눈에 구분된다.
- [ ] 출처, 기준일, 원본 위치가 보인다.
- [ ] 사람이 확인·수정·승인할 곳이 보인다.
- [ ] 통과한 테스트뿐 아니라 실패한 테스트도 보인다.
- [ ] 실제 연동되지 않은 기능을 작동한다고 말하지 않는다.
- [ ] 4주차 개선 항목에 담당·기한·완료기준이 있다.

## 8월 28일 결과물 약속

다음 항목이 있어야 약속으로 인정합니다.

- 최종 Agent·앱·결과물 이름
- Live Demo 입력·처리·결과·사람 승인
- 정상·오류·위험 시험과 판정기준
- 시간·오류·누락·수정 중 한 가지 성과증거
- 8월 22~27일 날짜별 담당과 완료증거
- 일정이 늦을 때 뺄 기능
- 8월 28일 이후 `계속·추가검증·중단` 제안

```text
8월 28일 [예시 입력]으로 [최종 결과]를 실제 실행하고,
[시험·README·시간 비교]로 완료 여부를 증명한다.
[날짜]까지 [핵심 기능]이 작동하지 않으면 [부가기능]을 제외한다.
```
